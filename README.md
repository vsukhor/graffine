Elementary transformations of graphs.

## Overview

***graffine*** is a header-only C++ library for constructing and modifying low-degree graphs (space-independent networks of edges and vertices).

While it operates on graphs of arbitrary geometry — provided that the max vertex degree does not exceed 4 — it is optimized for graphs containing abundant chains of linearly connected vertices.

## Core elements

Two major parts of ***graffine*** are **structure** which defines and holds graph elements, and a set of topological **transforms**, which modify that structure.

### Structure

***graffine*** stores a graph in layers of increasing complexity. The most elementary layer defines, as expected, a set of graph *edges* and *vertices*. Edges span between vertex pairs at the edge ends; the order of vertices within a pair defines edge directionality. Conversely, the outermost structural layer consists of disconnected *components*, each formed by mutually connected vertices and edges. Notably, ***graffine*** defines an intermediate layer of edge *chains*, which are linear runs of edges with no branches.

### Transformations

***graffine*** provides vertex degree-specific operators for modifying graphs at the elementary layer:

- Creation and deletion of edges and components
- Splitting and merging of edges
- Splitting and merging of vertices for each combination of degrees.

On top of these, ***graffine*** defines "pull" operations. These modify graph components by shifting an entire path of edges — spanned between two preselected vertices (a "driver" and a "source") — relative to the rest of the component.

Internally, all transformations are implemented as function object templates under [include/graffine/transforms/](include/graffine/transforms/).

### Additional features

- Adjacency and connectivity analyzers
- Path traversal
- PLY file I/O
- Graph integrity checks to verify internal consistency

## Usage

***graffine*** requires a C++23 compiler. The library is header-only and is consumed through the CMake target `graffine::graffine`, which provides the include paths and the C++23 requirement. It can be used either as an installed package:

```cmake
find_package(graffine 1 REQUIRED CONFIG)
target_link_libraries(my_app PRIVATE graffine::graffine)
```

or as a subproject, with `add_subdirectory(graffine)` or `FetchContent`, linking to the same target. Then include the relevant headers, e.g. `#include "graffine/structure/elements/graph.h"`.

The headers depend on `graffine/config_cmake.h`, which is generated from [config_cmake.h.in](include/graffine/config_cmake.h.in) into the build directory when the project is configured, and is installed alongside the other headers.

The PLY input/output relies on a modified version of the popular [tinyply](https://github.com/ddiakopoulos/tinyply) library, located in [external/tinyply/](external/tinyply) and made available by the `graffine::graffine` target. Its implementation is compiled in by defining `TINYPLY_AS_LIBRARY` before including `graffine/structure/io/ply.h` in exactly one source file of your program.

### Installing

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTS=OFF -DBUILD_EXAMPLES=OFF
cmake --install build --prefix <prefix>
```

installs the headers, the tinyply headers (under `include/graffine/external/tinyply`) and the CMake package files (under `share/cmake/graffine`). Pass `-DCMAKE_PREFIX_PATH=<prefix>` to projects calling `find_package(graffine)`. The install rules are generated by default only when ***graffine*** is the top-level project; set `GRAFFINE_INSTALL=ON` to enable them for a subproject.

### Building

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

The CMake options `BUILD_TESTS` (default `ON`), `BUILD_EXAMPLES` (default `ON`) and `BUILD_DOCS` (default `OFF`) control which targets are built. Setting `GRAFFINE_NATIVE_ARCH=ON` (default `OFF`) compiles with `-march=native`, which tunes the binaries for the build machine at the cost of portability.

Library configuration is passed through the following CMake variables, which are written into the generated `config_cmake.h`:

| Variable | Default | Meaning |
| --- | --- | --- |
| `GRAFFINE_FUNCTORS_VERBOSE` | `ON` | Transformation functors report verbosely |
| `GRAFFINE_PRINT_EDGES` | `ON` | Print detailed information on edges |
| `GRAFFINE_PRINT_VERTICES` | `ON` | Print detailed information on vertices |
| `GRAFFINE_DO_INTEGRAL_TESTS` | `ON` in Debug builds, otherwise `OFF` | Run graph integrity checks |
| `GRAFFINE_REAL_IS_DOUBLE` | `OFF` | Use `double` instead of `float` for real numbers |

These defaults apply only when ***graffine*** is the top-level CMake project. As a subproject, the variables default to `OFF`; set them before adding ***graffine*** to enable them. An installed package keeps the values it was configured with.

### Benchmarks

Benchmarks of graph construction, transformations and lookups use [Google Benchmark](https://github.com/google/benchmark), fetched at configuration:

```sh
cmake -S . -B build-bench -DCMAKE_BUILD_TYPE=Release -DBUILD_BENCHMARKS=ON -DBUILD_TESTS=OFF
cmake --build build-bench
build-bench/benchmarks/benchmarks
```

With `BUILD_BENCHMARKS=ON`, the reporting options `GRAFFINE_FUNCTORS_VERBOSE`, `GRAFFINE_PRINT_EDGES` and `GRAFFINE_PRINT_VERTICES` default to `OFF`, so that the benchmarks time the transformations rather than their console output. The benchmarks of single transformations keep the graph size constant, and report how their cost scales with it.

### Examples

A working [example](examples/create_merge_components/main.cpp) of a driver function using ***graffine*** creates a graph consisting of four linear components and subsequently merges two of them into one via a chosen pair of end vertices.

You can find additional usage examples within the extensive set of unit [tests](tests/).

### Applying transformations

Each transformation functor checks its preconditions before it modifies the graph, at a cost independent of the graph size (the checks of pulling from a degree 2 vertex copy the path), and offers three ways of applying it:

```cpp
graffine::transforms::vertex_merger::From<Deg1, Deg1, G> merge {gr};

merge(s1, s2);                     // throws precondition_error if not applicable
if (merge.is_applicable(s1, s2))   // only checks
    ...
if (auto res = merge.try_apply(s1, s2); !res)  // checks, then applies
    std::cout << res.error().reason;           // why it was not applicable
```

A rejected transformation leaves the graph unchanged. `try_apply` reports rejections without throwing, and without allocating: it suits simulations proposing many candidate moves, most of which may be rejected. `apply` performs the transformation without the checks, for arguments already known to be applicable.

### Processing non-topological properties

Transformations take an optional processor of non-topological properties (positions, weights...) as their last template parameter, `PP`, together with a `std::shared_ptr<PP>` at construction, and call its hooks before and after they change the graph. `PP` is `void` by default, for no processing.

The hooks are grouped by transformation family in members of the processor: `vertexMerger`, `vertexSplit`, `edgeCreation`, `edgeDeletion`, `edgeMerger`, `componentCreation`, `componentDeletion` and `pulling`, each with `on_start` and `on_end` overloads. Each family specifies the hooks it requires, with their arguments, as a concept `Processor` in its namespace, e.g. `graffine::transforms::vertex_merger::Processor<PP, G>`; [property_processor.h](include/graffine/transforms/property_processor.h) defines the concept `graffine::transforms::PropertyProcessor<PP, G>` of a processor usable by all transformations. A transformation instantiated with an unsuitable processor fails to compile with a report of the unsatisfied requirement. A processor implementing all the hooks is in [tests/property_processor.cpp](tests/property_processor.cpp).

### Error handling

***graffine*** never terminates the program on its own. Errors are reported by exceptions derived from `graffine::error` (itself a `std::runtime_error`), declared in [errors.h](include/graffine/utils/errors.h):

| Exception | Meaning |
| --- | --- |
| `graffine::io_error` | A graph file cannot be read or written, or does not describe a valid graph. |
| `graffine::precondition_error` | An operation was requested for graph elements that do not meet its requirements. |
| `graffine::invariant_error` | The internal bookkeeping of a graph was found inconsistent. The graph is left in an unspecified state and can only be destroyed. |

The consistency of a graph can be checked with `graffine::structure::IntegralTests`: its `validate()` returns a `std::expected` holding the first violation found, if any, while its call operator throws `invariant_error`.

In addition, Debug builds (those defining `DEBUG`) check many internal assumptions on hot paths. A failed check of this kind reveals a defect: it prints a diagnostic and calls `std::abort()`.
